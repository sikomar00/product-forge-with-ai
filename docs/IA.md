# IA v1.2 (승인 2026-11-09. v1.1에 Spec 인터뷰 결정으로 IA-20을 더했다)

기준: design.md 3절(게임 디자인)·8절(엔진), ADR-0004(읽기 전용 체크)·0006(구역 분리)·0009(콘텐츠 별도 리포), 2026-11-09 인터뷰 결정(아래 "결정" 절). 게임은 터미널 명령형이다. 명령 하나를 실행하면 결과를 보여 주고 끝나며, 답이 필요한 순간(퀴즈, 확신도, 설명 게이트, 예측, 감점 확인)에만 그 자리에서 묻는다. 명령 이름은 영어, 화면 문구는 한국어다(ADR-0008).

## 명령 구조

| ID | 명령 | 하는 일 | 근거 |
| --- | --- | --- | --- |
| IA-1 | `quest` | 홈. 등급·XP·연속 복습일, 현재 장 진행률, 현재 미션, 오늘 복습할 카드 수, 진행 중인 장애를 한눈에 본다 | design.md 3.9절 화면 예시 |
| IA-2 | `quest mission [ID]` | 미션 보기. 요청문과 카드를 읽는다. ID를 빼면 현재 미션 | 3.2절 핵심 루프, 3.3절 카드 |
| IA-3 | `quest check` | 채점. 체크마다 결과를 보고, 통과하면 보상·설명 게이트·카드 추가까지 이어진다 | 3.2절, ADR-0004 |
| IA-4 | `quest hint` | 다음 단계 힌트 하나(1→2→3). 감점을 알리고 확인을 받은 뒤 보여 준다 | 3.6절 |
| IA-5 | `quest solution` | 모범 답안. 감점(보상 20%만)과 복습 목록 추가를 알리고 확인을 받은 뒤 보여 준다 | 3.6절 |
| IA-6 | `quest map [장]` | 장 지도. 18장 진행률과, 장 안의 미션 목록(ID·유형 아이콘·코어/선택·AI 태그·상태) | 5절 |
| IA-7 | `quest exam` | 승급 시험. 현재 장의 보스를 남은 미션보다 먼저 도전하는 시험 모드로 들어간다 | 2026-11-09 결정 |
| IA-8 | `quest back` | 시험 모드나 복습 모드를 끝내고 일반 진행으로 돌아간다 | S1 `back` |
| IA-9 | `quest review` | 복습. 만기 카드 10~15장, 주 1회 재구성 복습(샌드박스), 장을 마치고 2주 뒤 지연 확인 퀴즈 | 3.7절 |
| IA-10 | `quest goals` | 졸업 기준 13개 영역의 현재 충족 상태 | 2.2절 |
| IA-11 | `quest stats` | 기록. 미션별 예상·실제 시간, 힌트 사용률, 확신했는데 틀린 비율, SQL 조회 | 3.7·3.8절 |
| IA-12 | `quest doctor` | 장비 점검. 도구 설치 여부와 허용 버전 범위 | 7.1절 |
| IA-13 | `quest incident status` · `abort` | 진행 중인 장애와 경과 시간 보기, 원상 복구 | ADR-0007 |
| IA-14 | `quest oncall start` · `stop` · `status` | 온콜 주간(12장 이후, 선택) 켜기·끄기·보기 | 3.7절 |
| IA-15 | `quest status --json` | 기계가 읽는 현재 상태. AI 튜터 모드가 읽는다 | 3.2절, 3.5절 학습 모드 |
| IA-16 | `quest help` | 명령 목록과 한 줄 설명 | S1 `help` |
| IA-17 | `quest reset` | 진행 초기화. 확인 문구를 입력해야 실행된다 | S1 `reset` |
| IA-18 | `quest update` | 콘텐츠 갱신. 콘텐츠 리포를 정해진 위치에 처음 받거나 최신으로 바꾼다. 갱신된 장과 새 미션 수만 보여 준다 | ADR-0009, UJ 결정 1 |
| IA-19 | `quest selftest` | 연동 확인. 받아 둔 실제 콘텐츠의 미션 테스트를 이 엔진으로 돌리고 통과·실패 개수만 보여 준다. 실패하면 미션 ID와 엔진 쪽 오류 위치만 보인다 | ADR-0006, UJ 결정 2 |
| IA-20 | `quest report [ID]` | 미션 오판 신고. 진단 정보(미션 키·화면 번호, 체크 번호별 결과, 버전)를 모아 보여 주고, 확인을 받은 뒤 비공개 콘텐츠 리포에 이슈를 연다 | Spec 결정, PRD 성공 지표 |

- 아무 명령 없이 `quest`만 치면 IA-1이다. 모르는 명령은 IA-16을 보여 준다.
- S1의 `run`·`schema`·`sql`은 SQL 게임 전용이라 가져오지 않는다. SQL 조회는 IA-11에 둔다.

## 화면별 내용

### IA-1 홈
- 머리: 게임 이름, 등급(견습·주니어·미들·시니어 후보), XP, 연속 복습일.
- 진행: 현재 장 이름과 진행 막대(통과 수/전체 미션 수), 오늘 복습할 카드 수.
- 현재 미션 한 줄: ID, 제목, AI 태그, 예상 시간. 시험·복습 모드면 모드 이름을 붙인다.
- 진행 중인 장애가 있으면 맨 위에 경과 시간과 함께 띄운다(IA-13).
- 복습 잠금 중이면 맨 위에 잠금 표시와 남은 만기 카드 수를 띄운다(아래 "복습 잠금").
- 맨 아래: 지금 할 수 있는 다음 명령 한 줄(예: `quest mission`, `quest check`).

### IA-2 미션 보기
1. 머리: ID, 유형 아이콘(🎫🧠🔮⌨️⚖️🔍🚨🏁), 제목, 코어/선택(➕), AI 태그(🔒🤝🚀), 예상 시간, 스캐폴딩 단계.
2. 요청문: 보낸 등장인물과 본문.
3. 카드: 개념·용법·도메인. 처음 나오는 도구는 🗺️ 도구 지도 카드를 먼저 보여 준다.
4. 작업 위치: OpsDesk 리포, 랩 VM, 샌드박스, 외부 서비스 중 어디서 하는지.
5. 다음 명령 안내.

### IA-3 채점
- 실습 미션(🎫): 체크마다 ✅/❌와 설명 한 줄, 실패한 체크에는 방향 힌트를 보여 준다. 트랩이 걸리면 💡 맞춤 메시지를 붙인다.
- 감사·장애 미션(🔍🚨): 통과한 체크 수와 방향만 보여 준다. 실패한 체크의 설명은 결함이나 원인의 위치를 알려 주므로 숨긴다.
- 퀴즈·드릴·예측·결정 미션: 그 자리에서 답을 묻고 바로 채점한다. 퀴즈와 예측은 확신도(1~3)도 묻는다.
- 통과하면: 보상 계산(기본 XP, 원샷 +20%, 힌트 감점) → 🤝·🚀 미션은 설명 게이트 질문 2~3개 → 카드가 복습 덱에 들어간다 → 다음 미션 안내.
- 시험 모드에서 보스를 통과하면 그 장에 남은 미션이 면제되고, 면제된 미션마다 보상 50%를 받는다.

### IA-6 장 지도
- 18장 목록: 장 번호와 이름, 등급 구간, 진행률. 잠긴 장은 이름만 보인다.
- 장 하나를 고르면 미션 목록: ID, 유형 아이콘, 코어/선택, AI 태그, 상태(안 함·진행 중·통과·면제).

### IA-15 기계용 상태 (`quest status --json`)
- 넣는 것: 현재 미션 ID, 미션 유형, AI 태그, 모드(일반·시험·복습), 남은 체크의 ID와 개수, 진행 중인 장애 여부.
- 넣지 않는 것: 체크 설명, 힌트, 모범 답안. AI 튜터가 이 값을 읽으므로 정답에 가까운 정보는 빼야 한다.

## 복습 잠금 (UJ 결정 3)
- 만기 카드가 20장(📐 추정치) 이상이면 새 미션(승급 시험 포함)이 열리지 않는다. IA-2·IA-7은 "복습 먼저" 안내와 남은 카드 수를 보여 준다.
- 진행 중인 미션, 장애 복구(IA-13), 복습(IA-9)은 막지 않는다.
- 복습해서 만기 카드가 20장 아래로 내려가면 바로 풀린다. 기준값은 텔레메트리를 보고 조정한다.

## 저장 위치 (학습자가 알아야 하는 곳)

| 무엇 | 어디 | 비고 |
| --- | --- | --- |
| 엔진 | `product-forge-with-ai` 리포(공개) | 사용자가 AI와 바이브코딩한다 |
| 콘텐츠 | 별도 비공개 리포(ADR-0009). `quest update`(IA-18)가 정해진 위치에 받아 둔다 | 학습자는 열지 않는다 |
| 설정 | `~/.config/quest/config.toml` | 제품 리포 경로, GitHub 소유자, 배포 URL, 랩 VM 호스트, 콘텐츠 경로 |
| 학습 상태 | SQLite 파일 하나(ADR-0003) | 정확한 위치와 백업 방법은 Spec에서 정한다 |
| 제품 | `opsdesk` 리포 | 학습자의 주 작업 공간 |
| 복습 샌드박스 | 빈 작업 폴더 | 위치는 Spec에서 정한다 |
| 랩 | Linux VM, k3d 클러스터 | 게임이 만들고 라벨을 붙인다(ADR-0007) |

- 학습자의 작업 공간(`opsdesk`, 샌드박스)은 엔진 리포와 콘텐츠 위치 밖에 둔다. 작업 공간에서 AI 도구를 써도 콘텐츠를 읽지 않게 하려는 것이다.

## 결정 (2026-11-09 인터뷰·승인)
1. 조작 방식: 명령형이고, 답이 필요한 순간에만 그 자리에서 묻는다.
2. 승급 시험은 보스를 먼저 도전하는 것이다(IA-7). 통과하면 남은 미션을 면제받고 면제된 미션마다 보상 50%를 받는다(S1 규칙).
3. 콘텐츠는 별도 비공개 리포에 둔다(ADR-0009).
4. 감사·장애 미션은 채점 결과에서 실패한 체크의 설명을 숨긴다(IA-3).
5. `quest status --json`에는 체크 설명·힌트·정답을 넣지 않는다(IA-15).
6. 0장(작업장)과 17장(Forge Run)에는 승급 시험이 없다. 0장은 이후 모든 장에 필요한 환경을 만들고, 17장은 처음부터 끝까지 해 보는 것 자체가 목적이다. S1도 0장과 7장(전환 심사)에서 시험을 막았다.

## UJ 인터뷰로 더한 결정 (2026-11-09 승인)
7. 콘텐츠는 `quest update`(IA-18)로 받는다.
8. 엔진과 실제 콘텐츠의 연동은 `quest selftest`(IA-19)로 확인한다.
9. 복습 잠금을 둔다(위 "복습 잠금").

## Spec 인터뷰로 더한 결정 (2026-11-09 승인)
10. 미션 오판은 `quest report`(IA-20)로 비공개 콘텐츠 리포에 이슈로 올린다. 이슈와 답글에도 스포일러 규칙을 적용한다.
