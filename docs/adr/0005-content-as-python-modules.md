# 미션 콘텐츠는 데이터 파일이 아니라 Python 모듈로 쓴다

체크는 함수다. 미션마다 파일이 있는지, API가 어떤 상태 코드를 돌려주는지, JSON의 어느 값이 맞는지를 조합해 판정해야 한다. S1도 미션을 Python 파일(`missions_sql.py`, `missions_py.py`)에 정의했다. 그래서 미션은 `content/chNN_*.py`에 미션 스키마(design.md 8.3절의 `Mission` dataclass)로 쓰고, 체크는 체크 프리미티브를 조합한 함수로 둔다.

## Considered Options
- YAML·TOML 같은 데이터 파일 + 체크 규칙 언어: 실행되는 코드가 아니어서 안전하고 읽기 쉽지만, 체크를 표현할 규칙 언어를 따로 만들어야 한다.
- 미션마다 독립 스크립트: 자유롭지만 공통 스키마가 없어서 엔진이 보상·힌트·복습을 일관되게 다룰 수 없다.

## Consequences
- 콘텐츠는 실행되는 코드다. 엔진은 이 리포의 `content/`만 불러온다.
- 엔진은 스키마를 통해서만 콘텐츠를 다룬다. 그래서 사용자는 콘텐츠를 열지 않고도 엔진을 만들 수 있다(ADR-0006).
- 스키마를 바꾸면 모든 콘텐츠가 영향을 받으므로, 스키마 변경은 Spec 개정으로 승인받는다.
