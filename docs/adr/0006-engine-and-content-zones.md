# 엔진 구역과 콘텐츠 구역을 나누고, 콘텐츠는 AI만 만든다

사용자는 이 게임의 학습자이면서 엔진을 직접 만드는 사람이다(2026-11-09 결정). 정답·힌트·체크를 미리 보면 그 미션의 학습 효과가 사라진다(design.md 8.6절). 그래서 리포를 두 구역으로 나눈다.
- **엔진 구역**: `quest/` 패키지, 체크 프리미티브와 그 테스트(`tests/test_checks_*`). 사용자가 AI와 바이브코딩한다.
- **콘텐츠 구역**: `content/`, `tests/test_missions_*`, 장애 시나리오, 모범 답안·힌트. AI만 만들고 사용자는 열지 않는다.

## Considered Options
- 사용자가 콘텐츠도 만든다: 직접 만든 미션은 풀어도 배울 것이 없다.
- AI가 엔진까지 만든다: 사용자 시간은 줄지만 엔진 제작을 실습 기회로 쓰지 못한다. 사용자는 바이브코딩을 골랐다(2026-11-09).

## Consequences
- 콘텐츠 작업 보고(채팅·커밋 메시지·PR 본문)에는 미션 ID, 개수, 테스트 결과만 쓴다. 미션 제목은 design.md에 공개돼 있어 숨기지 않는다.
- 콘텐츠가 든 PR은 GitHub에서 diff를 열면 내용이 보인다. 사용자는 diff를 열지 않고 테스트 결과로 머지를 승인한다.
- 힌트 3단계와 모범 답안은 난독화해 저장한다. 보안이 아니라 우연히 보는 것을 막는 용도다.
- 엔진 테스트는 실제 콘텐츠 대신 테스트용 가짜 미션(픽스처)으로 한다. 그래야 엔진을 고치다가 콘텐츠를 볼 일이 없다.
- 두 구역의 경계는 미션 스키마다(ADR-0005).
- 강제 수단은 없다(자율 준수).
