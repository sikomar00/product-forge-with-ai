# 채점은 화면 출력이 아니라 시스템 상태를 읽기 전용으로 검사한다

Product Forge의 실습 미션은 실제 도구로 실제 환경을 바꾸는 일이다(리포 설정, 배포, 컨테이너, 클러스터). 화면 출력 문자열은 도구 버전과 언어 설정에 따라 바뀌고, 학습자가 입력한 답만으로는 실제 상태를 증명할 수 없다. 그래서 체크는 상태를 읽기만 하고, CLI의 JSON 출력(`gh api`, `docker … --format json`, `kubectl -o json`, `terraform show -json`)이나 API 응답, 파일을 파싱해 판정한다(design.md 8.4절).

## Considered Options
- 화면 출력 문자열 비교: 만들기 쉽지만 도구 버전이나 로캘이 바뀌면 깨진다.
- 학습자가 결과를 입력: 퀴즈·드릴·예측 미션에는 이 방식을 쓴다. 실습 미션에서는 실제로 했는지 알 수 없다.

## Consequences
- 체크는 상태를 바꾸지 않는다. 상태를 바꾸는 일은 장애 주입(ADR-0007)만 하고, 별도 모듈(`quest/chaos/`)에 둔다.
- JSON 출력이 없는 도구는 그 도구가 만든 파일이나 리포트를 읽는다. 미션마다 허용 도구 버전 범위를 적고 `quest doctor`로 검사한다(design.md 7.1절).
- 체크 프리미티브마다 단위 테스트를 둔다(`tests/test_checks_*`, 엔진 구역).
