# 리뷰봇은 체크가 아니라 quest check 직전에 한 번 돈다

2장 리뷰봇은 게임이 로컬에서 학습자의 PR에 리뷰 코멘트를 단다(Spec 결정 11: 지적 목록을 공개 리포에 올리지 않으려고 GitHub Actions를 쓰지 않는다). 코멘트를 다는 것은 상태를 바꾸는 일이라 읽기 전용인 체크(ADR-0004) 안에 둘 수 없고, 미션을 볼 때는 아직 PR이 없을 수 있다. 그래서 리뷰 규칙이 있는 미션의 `quest check` **직전에, 채점과 따로** 돌린다. 학습자 본인이 연 가장 최근 PR에, 학습자 계정이 단 리뷰봇 리뷰가 아직 없을 때만 한 번 단다. 사용자 결정(2026-11-13).

## Considered Options
- 새 명령(`quest bot <PR 번호>`)을 둔다: 학습자가 PR을 연 뒤 직접 실행한다. 언제 도는지는 분명하지만 IA에 명령이 하나 늘고, 학습자가 잊으면 리뷰 없이 진행된다.
- 미션을 볼 때(`quest mission`) 돈다: 장애 주입과 같은 자리지만, 그때는 PR이 없는 경우가 많다.

## Consequences
- "한 번만"은 따로 기록하지 않고 PR의 리뷰로 판단한다. 이벤트 종류(ERD 22종)를 늘리지 않아도 되고, 몇 번 돌려도 결과가 같다.
- 공개 리포라 남이 연 PR이 있을 수 있다. 학습자 본인 PR(`--author @me`)과 학습자 계정이 단 리뷰만 본다(2026-11-13 보안 검토 반영).
- 리뷰봇이 실패해도(도구 없음, 네트워크) 채점은 그대로 하고 경고만 보인다.
- 리뷰봇은 체크 프리미티브가 아니라 `quest/labs/`에 있다. 상태를 바꾸는 일은 체크 밖에 둔다는 ADR-0004의 원칙을 따른다.
