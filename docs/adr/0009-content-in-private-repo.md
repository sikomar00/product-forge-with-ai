# 콘텐츠는 엔진 리포와 나눠 별도 비공개 리포에 둔다

사용자는 엔진을 AI와 바이브코딩한다(ADR-0006). AI 코딩 도구는 작업 중인 리포 안을 검색하므로, 콘텐츠가 같은 리포에 있으면 정답·체크가 검색 결과로 채팅에 나올 수 있다. GitHub PR diff에도 보인다. 게다가 엔진 리포 `product-forge-with-ai`는 공개 리포라서(2026-11-09 확인), 같은 리포에 두면 정답이 인터넷에 공개된다. 그래서 콘텐츠 구역(미션 모듈, 미션 테스트, 장애 시나리오, 모범 답안·힌트)을 별도 비공개 리포로 옮기고, 엔진은 설정 파일(`~/.config/quest/config.toml`)에 적힌 경로에서 콘텐츠를 불러온다. 사용자 결정(2026-11-09).

## Considered Options
- 같은 리포 + "엔진 작업 중에는 `content/`를 읽지 않는다" 규칙: 리포는 하나로 끝나지만 규칙만으로 막는다. 검색하다 내용이 보일 수 있고, 공개 리포라 정답도 공개된다.
- 엔진 리포 안에 비공개 서브모듈로 연결: 비공개는 지키지만, 받아 둔 서브모듈이 엔진 작업 폴더 안에 있어서 검색 노출 문제는 그대로다.

## Consequences
- 리포가 둘이 된다. 콘텐츠 리포의 이름은 Plan에서 정하고(예: `product-forge-content`), 사용자가 GitHub에서 비공개로 만든다.
- 엔진과 콘텐츠의 경계는 미션 스키마다(ADR-0005). 콘텐츠 리포는 엔진의 특정 버전을 고정해 쓰고, 콘텐츠 테스트(`tests/test_missions_*`)는 콘텐츠 리포의 CI에서 돈다.
- 비공개 리포의 GitHub Actions 사용량은 무료 포함량(GitHub Free 월 $12 사용액)에서 빠진다(design.md 11장).
- 랩 정의 가운데 정답이 드러나는 것(예: 리뷰봇이 지적할 항목 목록)도 콘텐츠 리포에 둔다.
- 콘텐츠는 학습자의 작업 공간(`opsdesk`, 복습 샌드박스) 밖의 정해진 위치에 받아 둔다(IA "저장 위치").
- 클라우드 세션의 AI가 콘텐츠를 만들려면, 사용자가 그 리포를 세션에 연결해 줘야 한다.
- 이 결정은 ADR-0005의 "이 리포의 `content/`"와 ADR-0006의 콘텐츠 구역 위치를 바꾼다. 두 구역을 나눈다는 원칙(ADR-0006)은 그대로다.
