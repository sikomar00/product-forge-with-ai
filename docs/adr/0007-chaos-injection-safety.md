# 장애 주입은 라벨 붙인 학습용 리소스에만, 원상 복구 수단이 있을 때만 한다

장애 미션(🚨)에서는 게임이 실제 환경을 일부러 망가뜨리고 학습자가 복구한다(design.md 3.4절). 대상을 잘못 고르면 맥의 시스템 파일이나 진행 중인 Tech Radar처럼 학습과 상관없는 것이 망가진다. 그래서 design.md 8.5절의 원칙을 결정으로 고정한다.
1. 대상은 OpsDesk의 로컬·프리뷰 환경, 랩 VM, k3d 클러스터, 게임이 라벨을 붙인 리소스로 한정한다. 맥 호스트의 시스템 파일과 Tech Radar는 건드리지 않는다.
2. 주입 전에 스냅샷을 남기고, `quest incident abort`로 언제든 원상 복구한다.
3. 운영(prod) 환경 주입은 17-7 Game Day에서만, 명시적 동의와 예약 시간대가 있을 때만 한다.
4. 과금 리소스를 만드는 주입은 하지 않는다.

## Considered Options
- 장애를 실제로 주입하지 않고 설명과 로그만 보여 준다: 안전하지만 실제로 진단하고 복구하는 경험이 생기지 않는다(design.md 2.1절의 "진단" 능력).
- 제한 없이 주입한다: 현실감은 크지만 되돌릴 수 없는 손상이 생길 수 있다.

## Consequences
- 장애 미션마다 inject·verify·cleanup과 abort 원상 복구 테스트를 갖춘다(design.md 8.7절 6번).
- 주입 대상인지 판별하는 라벨 규칙은 Spec에서 정한다.
- 장애 시나리오는 콘텐츠 구역에 둔다(ADR-0006).
