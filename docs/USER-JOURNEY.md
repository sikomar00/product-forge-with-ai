## UJ-1 첫날 설정과 0장 시작
1. 엔진을 설치한다(방법은 Spec에서 정한다).
2. `quest update`로 콘텐츠를 받는다. 콘텐츠 리포는 비공개라 이 맥의 GitHub 로그인이 필요하다.
3. `quest doctor`로 도구를 점검한다. 빠진 도구와 설치 명령(Brewfile)이 보인다.
4. `quest`로 홈을 열고, `quest mission`으로 0장 첫 미션을 읽는다.
5. 0장 마지막 진단 미션(0-9)에서 장마다 이해도를 적으면 `quest goals`의 초기값이 된다.
- 끝났을 때: 홈에 0장 진행 막대와 현재 미션이 보이고, `quest goals`에 초기 충족 상태가 있다.
- 실패하면 보이는 것: `quest update`의 인증 실패는 GitHub 로그인 방법을 안내한다. `quest doctor`는 빠진 도구와 허용 버전 범위를 보여 준다.

## UJ-2 미션 하나 풀기
1. `quest mission`으로 요청문과 카드를 읽는다. 처음 나오는 도구는 🗺️ 도구 지도 카드부터 본다.
2. 미션이 알려 준 작업 위치(OpsDesk 리포, 랩 VM, 외부 서비스)에서 실제로 작업한다. AI는 미션의 AI 태그대로 쓴다(UJ-8).
3. `quest check`로 채점한다. 체크마다 결과가 보인다.
4. 통과하면 보상을 받고, 🤝·🚀 미션은 설명 게이트 질문에 답한다. 카드가 복습 덱에 들어가고 다음 미션이 안내된다.
- 끝났을 때: 그 미션이 "통과"가 되고 다음 미션이 현재 미션이 된다.
- 실패하면 보이는 것: ❌ 체크와 방향 힌트, 흔한 실수면 💡 맞춤 메시지. 감사·장애 미션은 통과 개수와 방향만 보인다(IA 결정 4). 막히면 UJ-3.
- 복습 잠금이 걸려 있으면 다음 미션이 열리지 않고 UJ-4로 안내한다.

## UJ-3 막혔을 때
1. `quest hint`를 실행한다. 감점(힌트 하나에 보상 -20%)을 알리고 확인을 받은 뒤 1단계 힌트(방향)를 보여 준다.
2. 다시 시도한다. 필요하면 2단계, 3단계 힌트를 차례로 연다. 구체적인 명령은 3단계에만 있다.
3. 그래도 안 되면 `quest solution`으로 모범 답안을 본다. 보상은 20%만 받고, 그 미션이 복습 목록에 들어간다.
- 끝났을 때: 미션을 통과하고, 힌트와 모범 답안 사용이 기록된다(`quest stats`).
- 🔒 미션에서는 AI에게 묻지 않는다. 학습 모드의 AI는 개념 설명과 되묻기만 한다.

## UJ-4 매일 복습과 복습 잠금
1. `quest`(홈)에서 만기 카드 수, 예상 시간, 연속 복습일을 본다. 잠금이 걸려 있으면 맨 위에 보인다.
2. `quest review`로 만기 카드 10~15장을 그 자리에서 답한다. 퀴즈형 카드는 확신도(1~3)도 함께 입력한다.
3. 주 1회 재구성 복습: 예전 미션 하나를 빈 샌드박스에서 처음부터 다시 만든다. 그만두려면 `quest back`.
4. 장을 마치고 2주가 지나면 그 장의 지연 확인 퀴즈(핵심 10문항)가 복습에 나온다.
- 복습 잠금 규칙(결정 3): 만기 카드가 20장(📐 추정치) 이상이면 새 미션(승급 시험 포함)이 열리지 않는다. 진행 중인 미션, 장애 복구, 복습은 막지 않는다. 복습해서 20장 아래로 내려가면 바로 풀린다.
- 끝났을 때: 잠금이 풀리고 연속 복습일이 늘어난다.

## UJ-5 장애 대응
1. 장애 미션을 시작하면 게임이 스냅샷을 남기고 학습용 환경에 장애를 주입한다. 홈 맨 위에 경과 시간이 뜬다.
2. AI 없이(🔒) 증상을 관찰하고, 원인을 진단하고, 복구한다.
3. `quest check`로 복구를 확인한다. 통과 개수와 방향만 보인다. 통과하면 근본 원인 퀴즈에 답하고 MTTR이 기록된다.
4. 포스트모템을 쓴다.
- 끝났을 때: 복구 체크를 통과했고 MTTR과 근본 원인 분석이 남았다.
- 되돌리기: 끝내 못 고치거나 다른 곳까지 망가질 것 같으면 `quest incident abort`로 원상 복구한다. 미션은 미통과로 남는다.
- 온콜 주간: 12장 이후 `quest oncall start`를 켜 두면 일주일 동안 무작위 시각에 이미 클리어한 장애가 다시 일어난다. 같은 순서로 대응한다.

## UJ-6 승급 시험으로 장 건너뛰기
1. `quest exam`으로 현재 장의 보스에 시험 모드로 도전한다.
2. 보스를 푼다. 체크는 그 장 모든 산출물 체크를 포함한다.
3. 통과하면 남은 미션이 면제되고, 면제된 미션마다 보상 50%를 받는다. 그만두려면 `quest back`.
- 끝났을 때: 장이 끝나고, 면제된 미션은 장 지도에 "면제"로 보인다.
- 안 되는 경우: 0장과 17장에는 승급 시험이 없다(IA 결정 6). 복습 잠금 중에는 시험도 시작할 수 없다.

## UJ-7 장 마치기와 진행 확인
1. 보스를 통과하면 장이 끝난다. 등급 구간이 바뀌면 등급이 오른다.
2. `quest map`으로 다음 장을, `quest goals`로 졸업 기준 충족 상태를, `quest stats`로 예상·실제 시간과 힌트 사용률을 본다.
3. 1장과 2장을 마치면 `quest stats`의 실측치로 전체 일정을 다시 계산한다(design.md 3.8절).
- 끝났을 때: 다음 장이 열리고, 1·2장 뒤에는 다시 계산한 일정이 기록된다.

## UJ-8 AI 튜터와 함께 작업
1. OpsDesk 리포에서 AI 코딩 도구를 연다. 0-7에서 넣은 학습 모드 절에 따라, AI가 `quest status --json`으로 현재 미션 ID와 AI 태그를 읽는다.
2. AI는 태그대로 돕는다. 🔒는 개념 설명과 되묻기만, 🤝는 개념 질문과 리뷰(코드는 학습자가 먼저), 🚀는 생성해도 되지만 줄 단위 설명과 검증 체크리스트를 함께 낸다.
3. 작업을 마치면 `quest check`로 돌아간다(UJ-2).
- 끝났을 때: AI가 태그에 맞게 도왔고, 🚀 미션은 설명 게이트까지 통과했다.
- `quest status --json`에는 체크 설명·힌트·정답이 없다(IA 결정 5). 강제 수단은 없다(자율 준수).

## UJ-9 콘텐츠 갱신 받기
1. AI가 콘텐츠 리포에 다음 장을 올리고, 미션 ID·개수·테스트 결과만 보고한다(스포일러 규칙).
2. 학습자는 `quest update`를 실행한다.
3. 갱신된 장과 새 미션 수가 보인다. 내용은 보이지 않는다. `quest map`에 새 미션이 나타난다.
- 끝났을 때: 새 장을 플레이할 수 있다.
- 실패하면 보이는 것: 인증 실패는 GitHub 로그인 안내, 네트워크 실패는 이미 받아 둔 콘텐츠로 계속하라는 안내. 콘텐츠가 더 새 엔진 버전을 요구하면 엔진을 먼저 갱신하라고 안내한다.

## UJ-10 엔진 고치기와 연동 확인
1. 엔진 리포에서 AI와 함께 엔진을 고친다. 테스트는 가짜 미션 픽스처로 한다(`tests/test_checks_*`).
2. `quest selftest`를 실행한다. 받아 둔 실제 콘텐츠의 미션 테스트를 이 엔진으로 돌리고, 통과·실패 개수만 보여 준다.
3. 실패하면 미션 ID와 엔진 쪽 오류 위치(파일·줄)만 보고 엔진을 고친다. 원인이 콘텐츠 쪽이면 AI에게 콘텐츠 수정을 맡긴다.
- 끝났을 때: selftest가 모두 통과한 상태로 엔진 변경을 커밋한다.
- 콘텐츠 위치는 열지 않는다. 콘텐츠는 엔진 리포 밖에 있어서 엔진 작업 중인 AI의 검색에도 걸리지 않는다(ADR-0009).

## 결정 (2026-11-09 인터뷰)
1. 콘텐츠는 `quest update`(IA-18)로 받는다. 학습자가 콘텐츠 폴더에 들어갈 일을 없애기 위해서다.
2. 엔진과 실제 콘텐츠의 연동은 `quest selftest`(IA-19)로 확인한다. 개수와 엔진 쪽 오류 위치만 보여 준다.
3. 복습 잠금: 만기 카드가 20장(추정치) 이상이면 새 미션이 열리지 않는다. 진행 중인 미션, 장애 복구, 복습은 막지 않는다.

## 확인하지 못한 것
- 잠금 기준 20장과 복습 15분이 실제 플레이에 맞는지는 써 봐야 안다. 텔레메트리로 조정한다.
- 비공개 콘텐츠 리포를 맥에서 받을 때 쓸 GitHub 인증 방식(gh 로그인, SSH 키)은 Spec에서 정한다.
- `quest selftest`가 콘텐츠 내용을 가리면서도 엔진을 고칠 만큼 오류 위치를 보여 줄 수 있는지는 구현해 봐야 안다.
